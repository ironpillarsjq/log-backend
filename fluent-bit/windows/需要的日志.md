1. Security：最重要
重点关注以下事件组：
- 登录与提权：
  - 4624 登录成功
  - 4625 登录失败
  - 4634/4647 注销
  - 4648 使用显式凭据，例如 runas
  - 4672 登录会话获得敏感特权
  - 4776 NTLM 凭据验证
  - 域环境增加 4768/4769/4771 Kerberos 事件
其中要重点分析 4624 的登录类型：2 本地登录、3 网络登录、10 RDP 登录，以及来源 IP、工作站和 LogonId。微软登录审计说明
- 特权操作和进程：
  - 4688 进程创建
  - 4673/4674 敏感权限调用
  - 4704/4705 用户权限授予或移除
4688 非常关键，应同时开启“在进程创建事件中包含命令行”，否则通常只能看到程序路径，看不到执行参数。命令行可能包含密码等敏感数据，所以后端访问权限也需要控制。微软进程命令行审计说明
- 特权账号和组变更：
  - 4720/4722/4725/4726 创建、启用、禁用、删除用户
  - 4724 重置密码
  - 4738 用户属性修改
  - 4728/4729 域全局安全组成员变化
  - 4732/4733 本地管理员组成员变化
  - 4756/4757 通用安全组成员变化
  - 4739 域策略变化
尤其要监控用户加入 Administrators、Domain Admins、Enterprise Admins 等组。微软账号管理事件列表
- 持久化与痕迹清理：
  - 4697 安装服务
  - 4698–4702 创建、删除、启用、禁用或修改计划任务
  - 4719 审计策略被修改
  - 1102 Security 日志被清除
  - 4616 系统时间被修改
  - 4657 注册表值修改
  - 4670 对象权限修改
微软建议在高价值设备上对意外服务安装直接告警；计划任务也是常见的持久化手段。服务安装事件说明、计划任务事件说明
2. PowerShell Operational
你现在采集的是旧的 Windows PowerShell 通道，还应该增加：
Microsoft-Windows-PowerShell/Operational
重点事件：
- 4103 模块日志
- 4104 脚本块内容
- 4105/4106 脚本块开始与结束
需要在组策略中开启 PowerShell Script Block Logging，否则 4104 不会完整产生。微软 PowerShell 日志说明
3. Sysmon：强烈推荐
如果异常检测需要判断管理员“具体做了什么”，仅靠 Security 日志还不够。Sysmon 可以补充：
- 1 进程创建，包括父子进程、命令行、哈希
- 3 网络连接
- 10 进程访问，适合发现凭据转储行为
- 11 文件创建
- 12–14 注册表变化
- 17–18 命名管道
- 19–21 WMI 活动
- 22 DNS 查询
- 25 进程篡改
微软也建议对 Sysmon 进行过滤调优，否则日志量会比较大。微软 Sysmon 事件说明
